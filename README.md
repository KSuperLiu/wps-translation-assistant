# WPS 翻译助手 · 1.3.9

Windows WPS 表格 JavaScript 加载项。翻译人员继续直接在现有工作簿中编辑，右侧栏提供检查、定位和 AI 建议采用。游戏连接留待后续版本。

## 翻译人员工作流程（1.3.9）

1. 在 WPS 打开任务表，点击“翻译助手 → 打开助手”。接表确认会显示目标语言、工作表数及当前填写情况。多语言表先选择任务语言。
2. 点击“开始翻译 / 继续翻译”，定位全工作簿第一条可处理记录。原文有变化时显示删除与新增内容，旧译文可展开参考。
3. 继续直接在目标语言最终译文列编辑，提交单元格后自动检查，点击“下一条待处理”。也可在侧栏草稿中编辑，点击“写入并下一条”。下一条遵循当前列表中的工作表、搜索和任务筛选范围。
4. 点击“采用 AI 并写入”可直接将合格的表内 AI 建议写入当前译文；覆盖已有译文或不同的未写入草稿前会确认。也可先载入草稿编辑，核对后点击“写入并下一条”。草稿按工作簿、语言和条目隔离，在本次窗格会话保留；关闭/重载窗格或 WPS 后不保留。外部修改、排序或列结构变化使旧草稿失效，保留草稿并阻止覆盖。
5. 点击“交付检查”，重新扫描全工作簿，查看格式/Key 问题、识别提示和未写入侧栏草稿。允许原文或译文为空；格式通过不等于语义、术语或游戏效果已经人工审校。
6. 使用 WPS“文件 → 另存为”保存新的 `.xlsx` 交付文件，保留工作表、表头、Key 和格式。页面显示 WPS 当前文件的保存状态和位置；无法读取时明确提示，不宣称另存成功。助手不会自动保存或上传表格。

功能区仅保留“打开助手、下一条待处理、交付检查”。批量 AI 填充、撤销最近一次助手写入、特殊表头识别设置和检查更新位于“更多”。批量只填空白目标格，要求确认，并明确提示逐条人工复核。

“当前条目”从处理状态和原文开始显示。工作表、单元格、字段名和完整 Key 收在操作区下方默认折叠的“条目信息”中，需要时展开；完整 Key 后的“复制”按钮可复制该 Key，顶部“定位译文”仍可直接定位。

补译分类会核对当前译文，不会因为缺少旧译文而将已有译文归为待补译。原文发生变化时仍保留修订提示；格式问题单独检查，已填写不等于已审校。

检查换行标记的开关默认开启，设置保存在本机，切换立即重算译文、草稿、AI 建议和交付检查。存储受限时仅在本次窗格会话生效并提示；切换不修改工作簿或清除草稿。

任务列表不再提供“AI 建议与当前译文不同”筛选项。

本次 145 项测试通过，覆盖任务分类、草稿校验、AI 直接写入、冲突保护和撤销等。新版在本机 WPS 原生窗格中的完整安装与编辑验收尚未完成；不能将网页部署或模拟测试视为实机升级成功。

## 网页安装、更新与卸载

网站用于管理本机 WPS 插件，翻译仍在 WPS 中完成。无需手动下载/运行 EXE，无需 Node.js，也不需要上传翻译表。

1. 在已安装 WPS 的 Windows 电脑上打开网站，页面自动检测本机版本。
2. 点击唯一的主按钮“安装到 WPS”或“更新到 v…”。需要时自动调起 WPS 连接服务；根据浏览器提示允许打开 WPS / 连接本机服务。
3. WPS 正在运行时，保存并正常退出 WPS 文档，页面检测到退出后自动继续；等待期间可以取消，不再需要单独连接和勾选确认框。
4. 重开 WPS 表格，点击“翻译助手 → 打开助手”。安装后当前翻译功能可离线使用。
5. 以后回到同一网站更新；已是最新版本时主按钮直接显示状态。卸载、重新安装和重新检测收在“更多选项与帮助”中。

首页自动检测只读取状态，不自动安装、下载插件或唤起 WPS；只有点击操作按钮后才开始处理。等待过久会停止并提示重试，不会强行结束 WPS。写入结果不确定时会锁定重复提交，并允许只读复查确认。

安装网站采用单卡片、单主按钮。当前发布插件业务版本为 1.3.9，需要在网站点击更新后才能使用新版流程。WPS 明确返回安装服务不可用时会自动唤醒并有限重试；网络超时等未知结果不会自动重复提交。

简化页面已实测自动识别本机旧版本。当前本机 WPS 的安装/卸载接口另有服务不可用（HTTP 503）问题，唤醒后未恢复，完整的一键更新验收未通过；页面会明确报告未完成，旧版注册和资源仍保留。此限制与自动化测试、构建成功分别记录，不能据测试通过宣称所有目标环境均可安装。

**此前通过 EXE 安装的用户需要先从 Windows“设置 → 应用”卸载旧版一次。** 网页会检测 EXE 固定容器并阻止混装，避免 Windows 卸载项与网页版本不一致。之后统一通过网站管理。网页卸载使用 WPS 的停用接口，资源文件和识别设置缓存由 WPS 自身管理；它不代替旧 EXE 的系统卸载器。

需要 WPS 版本支持 JavaScript 加载项，且浏览器和企业策略允许访问 WPS 本机服务。网站使用 WPS 发布工具提供的 HTTP 本机回环通信，不要求修改安全设置。网页发布版本使用 WPS 标准的 `名称_版本` 目录，浏览器本地识别设置可能因资源地址或 WPS 缓存策略变化而需要重新配置。

## 维护 GitHub Pages

```powershell
npm.cmd ci
npm.cmd test
npm.cmd run site
```

`site-dist/` 是网站完整输出，包含安装界面、`latest.json`、本机通信模块和 `.7z` 插件包；不包含用户翻译表。`.github/workflows/pages.yml` 在 main 分支提交后自动运行测试、构建、校验并部署 Pages，PR 仅验证不部署。

插件业务代码更新时，先递增 package.json 的 version 并同步 package-lock.json，再提交。相同版本的资源包保持确定性；流水线会对照线上清单阻止同版本换包或发布降级。仅调整安装网站的文字和样式无需递增插件版本。该功能更新的是发布网站，用户安装的离线插件需要在网站上点击更新，不会后台自动升级。

仓库设置应将 Pages 来源设为 GitHub Actions。构建依赖 Node.js 22.12+ 和 Windows runner（wpsjs 的开发依赖含 Windows 原生组件）；使用者不需要安装这些开发工具。

## 已实现

- 按表头关系识别平铺翻译表及配置字段组，不限定 Sheet 名、C 列起始或每五列一组；兼容现有 LocalizationWorkbench 导出表。
- 识别目标语言；存在多种语言时要求选择，不自动猜测目标。
- 显示当前原文、旧原文变化、旧译文、最终译文草稿和 AI 建议；当前条目的位置与 Key 可展开“条目信息”查看。
- 校验 `{0}`、命名参数、`%s`、`%2$s` 等占位符和常用 TMP 标签，按出现次数检查，并检查标签闭合顺序。“更多 → 检查设置”可切换是否检查字面量 `\n`，默认开启，检查新增和遗漏；关闭后忽略换行标记数量差异，其他检查保持启用。
- 按工作表检查完整 Key 是否重复，不跨表判重；同一编号的不同字段后缀属于不同 Key。空译文计为未翻译，不再重复计为占位符缺失；错误 AI 建议单独显示，不计入当前译文错误数。
- 显示总条目、已填写、未翻译、校验问题条目和填写进度；有内容不代表校验通过。
- 按工作表、待处理、需补译、需修订、格式或 Key 问题、已填写、全部条目筛选，并搜索 Key、原文、旧译文、新译文和 AI 建议。
- 点击条目定位到原 Sheet 的新译文单元格；“下一条问题”在当前 Sheet/搜索范围内循环定位未翻译或校验错误。
- 单条 AI 建议可以直接写入，也可以先载入草稿；批量仅填充当前筛选中的空白译文，需确认。不会自动调用模型或产生翻译。
- 专用按钮撤销最近一次助手写入（包括人工草稿或批量 AI 填充）；已经被人工再次修改的单元格不会被强制还原。
- 选区变化同步侧栏；提交单元格编辑后检查变化的 Sheet，支持多格粘贴。切换工作簿后重新识别。
- 支持常见语言名、标准语种代码及地区/脚本标签；特殊表头可以通过“识别设置”映射一次，在同结构任务中复用。
- 侧栏显示当前版本，点击“检查更新”查询发布版本；发现新版后可直接打开更新网站。只在手动点击时联网读取版本清单，不传输翻译表内容，不自动升级或关闭 WPS。

## 开发者在本机启动

要求 Node.js 22.12+，以及支持 JavaScript 加载项的 Windows WPS Office。

```powershell
npm.cmd ci
npm.cmd run debug
```

不需要全局安装 wpsjs。命令启动本机开发服务并注册开发加载项。工具会选择可用端口，以终端显示的地址为准。保持该终端运行。

**首次添加加载项时，如果已打开的 WPS 没有出现新选项卡，请先保存工作、正常关闭全部 WPS 表格窗口，再打开 WPS。** 新建一个 Sheet 或工作簿不一定会重新加载功能区。

打开 `LanguagePatch_*.xlsx` 的任务副本，点击 **翻译助手 → 打开助手**。助手启动后会自动识别，也可以在 **更多 → 重新识别工作簿** 中刷新。

开发模式停止服务后不能继续使用加载项。发布安装后不需要本地开发服务。

## 备用交付：Windows 离线 EXE

可自行构建并分发 Windows 离线安装 EXE，或者 EXE 和说明的 ZIP。使用者无需 Node.js、npm 或网站；安装和插件运行均使用包内资源。支持 Windows 10/11，使用系统自带的 .NET Framework，不需要安装 .NET SDK。此方式与网页安装择一使用。

1. 使用者保存工作，正常关闭 WPS 文档窗口，双击 EXE，点击安装。
2. 重新打开 WPS 表格，点击“翻译助手 → 打开助手”。
3. 更新时双击新版 EXE 覆盖升级，无需先卸载。同版本可修复，旧包不会降级覆盖。
4. 卸载可从 Windows 设置的应用列表、开始菜单“卸载 WPS 翻译助手”或安装包的“卸载插件”进入。

安装仅对当前 Windows 用户生效，无需管理员权限。安装器只替换本插件的配置节点，保留其他插件；操作前备份，失败时尝试回滚。不会强行退出 WPS，也不修改翻译工作簿。

资源位于 `%APPDATA%\kingsoft\wps\jsaddons\WpsTranslationAssistant_1.0.0`；管理程序位于 `%LOCALAPPDATA%\Programs\WpsTranslationAssistant`；备份/日志位于 `%LOCALAPPDATA%\WpsTranslationAssistantData`。卸载删除受管资源和管理入口，保留未知用户文件、备份，不清理 WPS 浏览器缓存。

**目录中的 1.0.0 是固定加载容器版本，产品版本以安装清单和 Windows 应用列表为准。** WPS 根据 `name_version` 查找本地目录，因此容器的注册版本和目录名保持一致并长期固定；覆盖升级更新内部业务文件，避免更换地址导致本机存储丢失。从原 localhost/网站版首次迁移时，旧地址下的识别设置可能需重新配置。安装器不保证 WPS 自身的缓存清理策略。

开发者构建安装包：

```powershell
npm.cmd ci
npm.cmd run installer
```

构建脚本先生产构建，再运行 21 项安装引擎隔离测试及真实 Windows 卸载项/快捷方式隔离测试，使用 Windows 内置 C# 编译器生成独立 EXE，并生成校验文件、说明和分发 ZIP。测试与构建中间文件写入工作区 `work/native-installer-build`；交付文件写入项目的上级 `outputs` 目录。

源码中的 `installer/使用说明.txt` 是使用者说明模板。当前 EXE 未数字签名；需要签名的企业环境应由开发者/IT 使用组织证书签名，之后重新生成文件校验值并封装 ZIP。

## 识别约定

### 自动发现语种与列关系

- 识别 EN、KO、FR、DE、JA、ES、AR、ID、TH、VI、FIL 等标准二/三字母代码，不为每个语种单独编写表格解析分支。
- 统一大小写和下划线/连字符，如 `pt_BR` / `pt-BR`；支持 `zh-Hans`、`zh-Hant`、`es-419` 等地区或脚本标签，保留不同地区/脚本的区别。
- 兼容常见语言名、中文名和原生名称（例如 English、韩语、한국어、日本語），以及 JP→JA、KR→KO 等旧代码。名称识别还使用 WPS Chromium 的 Intl 语言数据；标准代码比任意自定义名称更可靠。
- 自动在前 12 行查找表头，允许前面有任务标题/说明；不再依赖工作表叫 `Language`。超出此范围的表头可通过“识别设置”指定。
- 平铺表按 Key、原文、语种表头识别，允许列重排；支持 LanguageKey / Key / Id、Source Text / Source / 原文 等表头。Id 与印尼语 ID 按列角色区分。
- 配置表通过上方字段名、`字段_i18N` / `字段_il8N` / `字段_key` 元数据和旧/新语种配对划分字段组，组宽可以变化，也可以插入备注列。字段组仍应具有可区分的字段边界；任意交错的多字段表可显式映射。
- 非标准原文表头（空白或中文字段说明）需要旧原文、Key 与目标语种关系提供足够依据，不通过翻译内容的字符猜测目标语种。
- 配置表中存在 KO (old) + KO 时，独立 EN 列作为参考语种；平铺多语种表保留各个未标记为参考的目标列。明确的“参考 EN”或“EN (reference)”不会成为写入目标。
- AI 列优先按语种或字段名对应。存在多个目标语种时，无法归属的通用 AI 列不分配给任意语种。
- 多个目标语种要求选择；重复语种别名列、重复 Key 映射、同等可信的多组表头会明确提示，不猜测写入位置。

### 特殊表头：配置一次，后续复用

展开侧栏的 **更多 → 识别设置**，选择工作表和表头行、首条数据行，再指定目标语种、字段名、Key 列、原文列、最终译文列，以及可选的旧原文/旧译文/AI 列，点击“保存 / 添加字段映射”。

同一结构可以添加多个字段或语种映射。手动映射启用后，该 Sheet 只处理已配置的字段；可以逐项移除，或点击“清除本结构的配置，恢复自动识别”。新译文列不能与其他字段的原文、Key、旧译文、AI 或新译文列重叠。

配置保存在插件浏览器环境的本机存储中，只包含表头结构及列角色，不保存译文正文，不写入源工作簿。后续同表头结构的任务会复用；表头发生变化时不会强套旧配置。清理 WPS 浏览器缓存、更换部署地址或环境禁用本机存储时可能需要重新配置，界面会提示本会话是否成功持久保存。

只对识别成功的条目统计；跳过的 Sheet 或异常字段会显示在“识别提示”中。为防止误把巨大的格式区域全部读入，单 Sheet 上限为 50,000 行、512 列、150 万个单元格，超过时明确跳过并提示。大范围修改后可手动重新检查。

## 写入与撤销边界

- “写入并下一条”、单条或批量 AI 写入及撤销会修改目标语言最终译文列；识别、校验、筛选、参考载入草稿和定位不修改表格内容或颜色。
- 采用前重新读取工作簿，核对 Key、原文、AI、当前译文和表头；预览之后排序、改表或切换工作簿时拒绝使用旧位置写入。
- 同一工作表内重复完整 Key、不合格 AI、合并单元格、目标公式或受保护的目标格不写入。批量预检查遇到这些写入限制时会停止，说明原因。
- 批量写入若中途失败，保留已成功部分的撤销记录并明确提示；不会宣称所有条目均成功。
- 文本写入时防止 `=` 等开头内容被解释为公式，写后核对结果并恢复原数字格式。
- “撤销最近一次助手写入”只保留该窗格会话内、每个工作簿最近一次成功写入。关闭/重载窗格、重启 WPS 或另存改名后不保证保留。它不接管 WPS 的 Ctrl+Z，也不是跨会话草稿系统。
- 插件直接修改当前工作簿的内存内容，不自动保存，不实现“原始文件始终只读”。请在任务副本上编辑，并使用 WPS 保存/另存。
- 校验覆盖范围与现有工作台规则一致，不是完整的 TMP 语法或 UI 排版验证器，不判断文字是否溢出。
